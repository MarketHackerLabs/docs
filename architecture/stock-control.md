# Контроль FBS-остатков

## Назначение

Модуль `stock_control` — bounded context для контроля FBS-остатков Wildberries и Ozon. Он хранит физический остаток организации, получает выставленные остатки и FBS-заказы через официальные API, строит рекомендации и открывает алерты. Общая карта товаров и артикулов площадок принадлежит модулю `product_matching`.

В v1 поддерживается только FBS. FBO и FBW отбрасываются адаптерами и не попадают в снимки, рекомендации и интерфейс. MarketHacker никогда не записывает остатки на маркетплейсы: продавец применяет рекомендации вручную.

## Границы модуля

`marketplace_accounts` используется только как якорь кабинета организации. Официальные API-токены продавца хранятся в отдельной vault-таблице `stock_control_api_credentials` в зашифрованном виде. Они не хранятся в `MarketplaceCredentialVault`, не зависят от Guided Connect и не используются через `wb_gateway`.

Для синхронизации достаточно неархивного кабинета и активного API-токена в vault-таблице модуля. Статус portal-подключения кабинета не определяет доступность синхронизации.

Физический остаток — одно число `physical_qty` на товар из `product_matching`. Оно изменяется только через журнал движений. Остатки маркетплейсов хранятся по кабинету, листингу и складу площадки; склады не суммируются в одну витрину.

## Ограничение тарифа и доступ

Фича тарифа: `stock_control`, `grant_scope = org`. Если фича отсутствует, backend поднимает `PlanLimitError`, HTTP API отвечает `402`.

Владелец организации управляет API-токенами, физическим остатком и настройками. Карта соответствий имеет отдельный API без ограничения фичей тарифа. Участник видит только склады и алерты привязанных к нему кабинетов.

## Синхронизация

ARQ cron запускается каждые 15 минут: `minute={0,15,30,45}`. Интервал является настройкой платформы и не передаётся продавцу.

Каждый неархивный кабинет с активным токеном синхронизируется независимо:

1. Адаптер получает FBS-остатки по складам и изменения FBS-заказов.
2. Заказы создают идемпотентные движения физического склада.
3. Снимки обновляются отдельно по каждому складу WB или Ozon.
4. Модуль пересчитывает алерты и рекомендации.

Ошибка одного кабинета не останавливает остальные. При недоступности метода остатков допускается режим оценки по заказам; он не создаёт неизвестные остатки.

## REST API

Префикс для Manager Portal и расширения:

`/api/v1/organizations/{org_id}/stock-control`

| Метод | Путь | Назначение |
|-------|------|------------|
| `PUT` | `/accounts/{account_id}/api-token` | Сохранить и проверить официальный API-токен |
| `DELETE` | `/accounts/{account_id}/api-token` | Удалить API-токен |
| `GET` | `/accounts/{account_id}/api-token/status` | Получить статус токена без секрета |
| `POST` | `/skus/{sku_id}/ledger/set` | Установить физический остаток через журнал |
| `POST` | `/skus/{sku_id}/ledger/adjust` | Добавить ручную дельту в журнал |
| `GET` | `/settings` | Получить настройки организации |
| `PATCH` | `/settings` | Изменить резерв и порог малого остатка |
| `GET` | `/board` | Получить страницу SKU, изображения, остатки, склады и рекомендации |
| `GET` | `/alerts` | Получить открытые алерты |
| `POST` | `/telegram/link` | Начать привязку Telegram |
| `DELETE` | `/telegram/link` | Отвязать Telegram |

Публичный webhook Telegram не входит в org-префикс:

`POST /api/v1/stock-control/telegram/webhook`

`GET /board` сначала применяет поиск `q` по внутреннему SKU и SQL-пагинацию (`page`, `pageSize`), затем строит рекомендации только для выбранной страницы. `attention=true` оставляет товары с открытым советом по превышению выставленного остатка или перераспределению, нулевым физическим остатком либо без снимков складов.

Во время синхронизации Wildberries соответствие `chrtId` → `nmID` из content cards обновляет `catalog_id` листинга. URL обложки в БД не хранится: доска собирает его на лету из `catalog_id`.

## Клиенты и Telegram

Manager Portal: ключи площадок — в настройках кабинета (`/accounts/{id}`), отдельно от входа в кабинет продавца. Импорт соответствий вызывает API `product_matching`, а доска и Telegram остаются на `/stock-control`. Браузерное расширение использует тот же REST API; новые экраны расширения в v1 не добавляются.

Уведомления продавца отправляет отдельный Telegram-бот. Его токен задаётся в `stock_control_telegram_bot_token` и не совпадает с токенами support- или notify-ботов. Привязка пользователя к организации хранится отдельно; сообщения фильтруются по доступным пользователю кабинетам.
