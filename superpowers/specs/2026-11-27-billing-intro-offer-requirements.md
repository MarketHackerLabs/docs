# Биллинг: вводный оффер за N ₽ на N дней

Дата: 2026-11-27  
Статус: implemented (см. design + plan; UI расширения — отдельный трек)  
Источник: уточнение с PM (Влад), 27.11.2026

## Цель

Дать пользователю оформить **платный тариф** (на старте — **Личный / `pro`**) за символическую сумму на короткий период, с автоматическим списанием **полной monthly-цены выбранного тарифа**, если карта привязана и подписка не отменена.

Оффер не должен быть зашит только под `pro`: целевой тариф задаётся настройкой, в будущем тот же механизм может работать с любым платным тарифом.

## Контекст продакшена

На проде каталог тарифов такой:

| Тариф | slug | Месяц | Год |
|--------|------|-------|-----|
| Бесплатный (пробный) | `free` | 0 ₽ | 0 ₽ |
| Личный | `pro` | 1990 ₽ | 9990 ₽ |
| Командный | `enterprise` | 4990 ₽ | 49990 ₽ |

Первый сценарий: вводный оффер на **`pro`**, затем автосписание **1990 ₽/мес**. Название «пробный» у `free` к этой механике не относится.

### Что это не является

| Существующая сущность | Почему не подходит |
|------------------------|--------------------|
| Тариф `free` («Бесплатный (пробный)») | Бесплатный план каталога; к оплате N ₽ и автосписанию полной цены не относится |
| Промотип `trial` | Бесплатные дни по коду, по истечении → без автосписания полной цены |
| Промотип `discount` | Скидка на первый платёж при upgrade; не отдельный вводный период «N ₽ / N дней» |
| Промотип `free_period` | Бесплатный период без оплаты |

Новая механика: **платный вводный период выбранного тарифа + автопродление по полной monthly-цене этого тарифа**.

## Решения (зафиксировано)

| Тема | Решение |
|------|---------|
| Модель настройки | Ближе к **глобальной настройке**, не к полям одного тарифа. Точная форма хранения — на design; важно не привязывать логику жёстко к `pro` |
| Целевой тариф | Выбирается в настройке оффера; на старте — `pro`, в будущем может быть любой платный |
| Billing period | **Только monthly**. Yearly вводный оффер не поддерживается |
| «Уже покупал» | Учитываются **только оплаты подписки**. Докупки лимитов и прочие платежи не считаются |
| Статус во вводном периоде | **Отдельный** статус подписки (не reuse `trialing` / `active` как есть) |
| Действия во вводном периоде | Можно сразу перейти на **полную оплату текущего целевого тарифа** или на другой платный (в т.ч. `enterprise`) |
| Win-back | **Оба рычага в scope**: глобальная галочка + точечная выдача пользователю. Реализовывать полностью |
| Повтор win-back | Только через **выдачу админом** (точечное разрешение) |
| Клиенты | Нужен в **`manager_portal`** (UI в этом треке). Для **`browser_extension`** — API + интеграционная документация; UI расширения делает другой разработчик |

## Must-have

### Вводное предложение

| Параметр | Требование | По умолчанию / старт |
|----------|------------|----------------------|
| Цена вводного периода | Настраивается в админке | **1 ₽** |
| Длительность | Настраивается в админке | **7 дней** |
| Целевой тариф | Выбирается в глобальной настройке оффера | **`pro`** |
| Период биллинга после вводного | Только monthly | полная monthly-цена целевого тарифа (для `pro` — **1990 ₽/мес**) |

Одновременно в системе может быть **один** активный такой вводный оффер (не несколько конкурирующих).

### Кто может купить

Базовый доступ:

- пользователь **без успешных оплат подписки** (докупки лимитов не блокируют).

Дополнительно (win-back):

- если включена **глобальная галочка** — оффер доступен и тем, у кого уже были оплаты подписки;
- и/или пользователю выдано **точечное разрешение** админом.

Повторный доступ после использования — только новой точечной выдачей админом (не «раз в год» автоматически).

### Жизненный цикл

1. Пользователь (если eligible) оплачивает вводную цену (N ₽).
2. Подписка переходит в **отдельный статус вводного периода**; доступ = лимиты/фичи **целевого тарифа** оффера на N дней.
3. Карта сохраняется для рекуррента (как при обычной подписке ЮKassa).
4. Через N дней система автоматически списывает **полную monthly-цену целевого тарифа**, **если**:
   - карта не отвязана;
   - пользователь не отписался (не отменил автопродление / подписку).
5. Если карта отвязана или пользователь отписался — полного списания нет; доступ заканчивается с окончанием вводного периода.
6. Во время вводного периода пользователь может **сразу** оформить полную оплату целевого тарифа или перейти на другой платный тариф (например `enterprise`) — без ожидания конца N дней.

Подтверждено PM: «отдал рубль → через N дней отдал фулл».

### Админка

- Глобальная настройка оффера: вкл/выкл, цена (₽), длительность (дни), целевой тариф, глобальная галочка win-back для уже плативших подписку.
- Значения по умолчанию: 1 ₽ / 7 дней / целевой тариф `pro`.
- Точечная выдача / снятие права на вводный оффер конкретному пользователю.
- Валидация: не более одного активного вводного оффера; billing period оффера — только monthly.

### Manager-portal

- Показ и оформление вводного оффера для eligible пользователей (в этом треке).

### Интеграция расширения

- Backend API + документация в `docs/integrations/` для другого разработчика.
- Код `extension-chrome` в этом треке **не меняем**.

## Scope

### In (MVP)

1. Один глобально настраиваемый вводный оффер (целевой тариф выбирается; старт — `pro`).
2. Eligibility: нет успешных оплат подписки **или** глобальный win-back **или** точечная выдача админом.
3. Оплата N ₽ → отдельный статус → доступ целевого тарифа на N дней → автосписание полной monthly-цены при сохранённой карте и без отписки.
4. Во вводном периоде — возможность сразу купить полную monthly-цену целевого тарифа или другой платный тариф.
5. Админка: цена, дни, целевой тариф, вкл/выкл, глобальный win-back, точечная выдача пользователю.
6. UI оформления в `manager_portal`.
7. Поведение при отписке / отвязке карты до конца вводного периода — без полного списания.
8. Интеграционная документация для разработчика расширения.

### Out (MVP)

- Отдельный тариф в каталоге под вводный оффер.
- Yearly-вариант вводного оффера.
- Изменение прайса каталога `free` / `pro` / `enterprise` как такового.
- Переиспользование промотипов `trial` / `discount` / `free_period` как замену этой механике.
- Изменения в `extension-chrome` (другой разработчик).

## Критерии приёмки

1. Eligible пользователь без оплат подписки может оформить вводный оффер за цену из админки на N дней (monthly-only).
2. После успешной оплаты вводного платежа подписка в **отдельном статусе**, effective plan = целевой тариф оффера до конца периода.
3. По окончании периода при активной карте и без отписки — списание полной monthly-цены целевого тарифа и переход на обычную подписку.
4. При отписке или отвязке карты до конца периода — полного списания нет; доступ прекращается по правилам отмены / истечения.
5. Во вводном периоде доступен переход на полную оплату целевого тарифа и на другой платный тариф.
6. Глобальная галочка win-back открывает оффер пользователям с историей оплат подписки.
7. Точечная выдача админом даёт оффер конкретному пользователю; повтор — только новой выдачей.
8. Параметры оффера (цена, дни, целевой тариф, флаги) меняются в админке без деплоя.
9. Одновременно не существует нескольких независимых активных вводных офферов.
10. В `manager_portal` eligible пользователь видит и может оформить оффер.
11. Есть интеграционная документация для разработчика расширения: eligibility, оформление, статусы, ошибки для UI.
